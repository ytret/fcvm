== The FCVM processor

The FCVM CPU is a 32-bit load/store machine with a small, variable-length
instruction set: 8 general-purpose 32-bit registers, a 32-bit stack pointer, a
single flat address space with memory-mapped devices, and maskable interrupts
vectored through a table at address `0x00000000`. It supports only little-endian
data, and it has no floating-point unit, no memory management unit and no
instruction cache.

This chapter describes the programming model of the CPU: its registers and flags,
its memory model, the instruction execution cycle, and how faults and interrupts
are handled.

=== Programming model

The CPU is a 32-bit load/store machine. All computations are performed on 32-bit
values held in registers; memory is accessed only by the `LDR` and `STR`
instructions.

==== General-purpose registers

The CPU has eight general-purpose 32-bit registers, `R0` to `R7`. All of them are
equivalent: any register can be used as a source or as a destination operand of any
instruction. There is no dedicated accumulator or index register.

==== Stack pointer

The stack pointer (`SP`) is a dedicated 32-bit register. The stack grows downwards:
`PUSH` subtracts 4 from `SP` before storing a 32-bit value, and `POP` reads a 32-bit
value and then adds 4 to `SP`. The stack is not bounded by the ISA; see
<<stack-overflow>> for the two conditions that are reported as a stack overflow.

`SP` can be referenced by any instruction that takes a register operand, using
register code `0x08`.

NOTE: The CPU does not initialize `SP` when it leaves the reset state. Software must
set `SP` to a valid stack address (and leave room for it in memory) before it uses
`PUSH`, `POP`, `CALL`, `RET`, `INT` or `IRET`.

==== Program counter

The program counter (`PC`) is a dedicated 32-bit register that holds the address of
the next instruction to be fetched. `PC` is updated implicitly by every instruction
and can be modified explicitly by the branch, call and return instructions.

`PC` cannot be used as an operand. Register codes `0x00` to `0x08` address the
general-purpose registers and `SP`; there is no register code for `PC`.

.Processor registers
[#registers]
[%header,cols="1,1,1,1,3"]
|===
|Register |Code |Width |Reset value |Description
|`R0`--`R7` |`0x00`--`0x07` |32 bits |`0x0000_0000` |General-purpose registers.
|`SP` |`0x08` |32 bits |`0x0000_0000` |Stack pointer. Decremented by `PUSH`,
incremented by `POP`.
|`PC` |-- |32 bits |Value of IVT entry 0 |Program counter. Not addressable as an
operand.
|===

==== Flags

The CPU keeps four flags in a status byte: zero (`Z`), sign (`S`), carry (`C`) and
overflow (`V`). The arithmetic and logic instructions update the flags; the branch
instructions read them. The flags are not directly readable or writable by any
instruction.

.Flags
[#flags]
[%header,cols="1,1,4"]
|===
|Bit |Name |Description
|7:4 |Reserved |Reserved. Always zero.
|3 |`V` |Overflow. Set when a signed arithmetic operation overflowed.
|2 |`C` |Carry. Set when an unsigned addition or subtraction produced a carry or no
borrow, and set by the shift instructions to the last bit shifted out.
|1 |`S` |Sign. Set to bit 31 of the result of the last flag-setting operation.
|0 |`Z` |Zero. Set when the result of the last flag-setting operation was zero.
|===

At reset, all flags are reset.

[[memory-model]]
=== Memory model

The CPU has a single flat address space of `2^32^` bytes, addressed by 32-bit
values. All data is little-endian: in a 32-bit value, byte 0 (the least significant
byte) is stored at the lowest address.

The interrupt vector table occupies the first 1024 bytes of the address space, at
addresses `0x0000_0000` to `0x0000_03FF`. The rest of the address space is populated
by memory-mapped regions registered with the memory controller. Devices are mapped
into this space by the bus controller; refer to the peripherals manual for the
device memory map.

The CPU imposes no alignment requirement on instructions or data. Any alignment or
access-size restriction is imposed by the memory-mapped region that is accessed: the
region must be mapped and must support the requested access width, and a 32-bit
access must lie entirely inside the region. A violation is reported as a bad memory
access exception (see <<exceptions>>).

=== Instruction execution model

The CPU executes one instruction at a time, in four steps:

. Fetch the opcode byte at the address in `PC`.
. Decode the operands of the instruction, in the order defined in
<<instruction-set>>, advancing `PC` past each decoded operand.
. Execute the operation.
. Continue with the next instruction, unless the instruction changed `PC`.

The following rules apply:

* Instructions are variable-length: an instruction consists of the opcode byte
  followed by its operands (see <<instruction-encoding>>).
* At the start of the execute step, `PC` holds the address of the instruction that
  follows the current one. Relative branches are an exception: the displacement of
  `+imm8` is relative to the address of the branch instruction itself, not to `PC`.
* The CPU checks for pending interrupts before it fetches an instruction, or while
  it is halted. An interrupt therefore takes effect between two instructions.

[[exceptions]]
=== Exceptions

An exception transfers control to a handler whose address is taken from the
interrupt vector table (IVT). The IVT is an array of 256 32-bit entries at address
`0x0000_0000`; the address of entry _n_ is `4 * n`.

.Exception and interrupt vector table
[#ivt]
[%header,cols="1,2,4,1"]
|===
|Number |Type |Cause |Address
|0 |Reset |CPU reset. |`0x0000_0000`
|1 |Bad memory access |Unmapped address, unsupported access width, or a 32-bit
access crossing the end of a region. |`0x0000_0004`
|2 |Bad instruction |Unknown opcode, invalid register reference, invalid `imm5`, or
invalid IRQ line number. |`0x0000_0008`
|3 |Division by zero |`DIV` or `IDIV` with a zero divisor. |`0x0000_000C`
|4 |Stack overflow |`SP` underflow or overflow on a stack operation; see
<<stack-overflow>>. |`0x0000_0010`
|5--31 |Reserved |Reserved for future exceptions. |`0x0000_0014`--`0x0000_007C`
|32--63 |Interrupt |Device interrupt on IRQ line 0--31. |`0x0000_0080`--`0x0000_00FC`
|64--255 |Reserved |Reserved. |`0x0000_0100`--`0x0000_03FC`
|===

When an exception or interrupt is taken, the CPU:

. Pushes `PC` onto the stack, unless the entry number is 0 (reset, which does not
  push).
. Loads `PC` with the 32-bit handler address from the corresponding IVT entry.

The value pushed onto the stack depends on the source:

* For an interrupt, the pushed `PC` is the address of the instruction that would
  have been executed next. Returning from the handler resumes the interrupted
  program.
* For an exception, the pushed `PC` is the address of the faulting instruction, so
  executing `IRET` retries the instruction. A handler that does not want to retry
  must modify the saved value (or the stack pointer) accordingly.

The CPU counts every exception. If it takes a third exception without a reset in
between, it enters the triple-fault state and resets the CPU.

[[interrupts]]
=== Interrupts

The CPU has 32 interrupt request (IRQ) lines, numbered 0 to 31. Each line maps to
IVT entry `32 + line`, that is, entries 32 to 63.

An IRQ line is set to the pending state by a device, by the bus controller, or by
the `INT` instruction. The pending state is a single bit per line; raising a line
that is already pending has no additional effect.

The CPU services interrupts as follows:

* Pending IRQs are checked before an instruction is fetched, or while the CPU is
  halted.
* When more than one line is pending, the lowest-numbered line is serviced first.
* A serviced line is cleared automatically. The handler is responsible for clearing
  the request at the device.
* The CPU pushes `PC` and jumps to the handler address. `IRET` returns from the
  handler by popping `PC`.

Interrupts are not masked by the CPU. Software that must not be interrupted has to
use other means of synchronisation, for example disabling the interrupt source at
the device.

[[instruction-encoding]]
== Instruction encoding

This chapter describes how instructions are encoded. The operand list of each
individual instruction is given in <<instruction-set>>.

=== Instruction format

Every instruction begins with a one-byte opcode, followed by zero or more encoded
operands:

.Instruction format
[#instr-format]
[%header,cols="1,1,4"]
|===
|Field |Size |Description
|Opcode |1 byte |Identifies the operation and the operand layout. See
<<opcode-map>>.
|Operands |0--6 bytes |Immediate values and register references, in the order listed
in the instruction description. See <<operand-encoding>>.
|===

An instruction is between 1 and 7 bytes long. No padding or alignment is used.

=== Opcode map

The three most significant bits of the opcode (bits 7:5) select the instruction
class. The remaining bits select the variant within the class.

.Opcode map
[#opcode-map]
[%header,cols="1,1,1,3"]
|===
|Bits 7:5 |Class |Opcode range |Instruction groups
|`000` |Reserved |`0x00`--`0x1F` |Reserved. Opcode `0x00` is never valid and raises
a bad instruction exception.
|`001` |Data movement |`0x20`--`0x3F` |`MOV`, `STR`, `LDR`.
|`010` |Arithmetic and logic |`0x40`--`0x5F` |Arithmetic, logic, shift, rotate,
compare and test instructions.
|`011` |Flow control |`0x60`--`0x7F` |Branches, conditional branches, `CALL`, `RET`.
|`100` |Stack |`0x80`--`0x9F` |`PUSH`, `POP`.
|`101` |Miscellaneous |`0xA0`--`0xBF` |`NOP`, `HALT`, `INT`, `IRET`.
|`110`--`111` |Reserved |`0xC0`--`0xFF` |Reserved.
|===

Within the flow control class, opcodes are allocated in blocks of four, one block
per branch condition. Within a block, the two least significant bits select the
target operand:

.Encoding of flow control operands
[#flow-operand-form]
[%header,cols="1,3"]
|===
|Bits 1:0 |Target operand
|`00` |Relative: signed 8-bit displacement (`+imm8`).
|`01` |Absolute: 32-bit immediate address (`imm32`).
|`10` |Register: the contents of a register reference (`RD`).
|`11` |Not used.
|===

`RET` does not follow this pattern: it has no operands and occupies the last opcode
of the class.

NOTE: Opcode values are not listed in this manual. Byte 0 of every encoding table
names the `CPU_OP_*` macro that defines the opcode; the numeric values of those
macros are given in `inc/fcvm/cpu_instr_descs.h`.

[[operand-encoding]]
=== Operand encoding

Two kinds of operands exist: immediate values and register references. The operand
types of an instruction are fixed by its opcode; the decoder does not inspect
operand data to decide how to decode it.

==== Immediate operands

.Immediate operand types
[#imm-operands]
[%header,cols="1,1,3"]
|===
|Notation |Size |Description
|`imm5` |1 byte |5-bit unsigned value, `0` to `31`. Bits 7:5 must be zero; a
non-zero value raises a bad instruction exception.
|`imm8` |1 byte |8-bit value. Interpreted as unsigned, or as a signed displacement
when the instruction specifies `+imm8`.
|`imm32` |4 bytes |32-bit value, little-endian.
|===

==== Register references

A register reference is always one byte. It selects a register and an access size.

.Register reference encoding
[#reg-ref]
[%header,cols="1,1,4"]
|===
|Bits |Field |Description
|7 |Reserved |Reserved. Must be zero; a one raises a bad instruction exception.
|6 |Access size |`0`: 32-bit access, the whole register. `1`: 8-bit access, the lower
byte of the register. Honoured only by `STR` and `LDR`; all other instructions
ignore this bit and always access the full 32-bit register.
|5:0 |Register code |Selects the register; see <<reg-code>>. Codes `0x09` to `0x3F`
are reserved and raise a bad instruction exception.
|===

.Register codes
[#reg-code]
[cols=">2h,9*^.^"]
|===
|Code |`0x00` |`0x01` |`0x02` |`0x03` |`0x04` |`0x05` |`0x06` |`0x07` |`0x08`
|Register |`R0` |`R1` |`R2` |`R3` |`R4` |`R5` |`R6` |`R7` |`SP`
|===

Encoding examples:

* `0x04` -- access size `0`, register code `0x04`: 32 bits of `R4`.
* `0x48` -- access size `1`, register code `0x08`: the lower byte of `SP`.

[[instruction-set]]
== The FCVM instruction set

This chapter lists every instruction of the FCVM ISA and describes its syntax,
operation and effect on the flags.

Instructions are grouped by function. The grouping is for readability only: the
opcode class (see <<opcode-map>>) determines how the CPU decodes an instruction,
not the group in which it is presented here.

=== Instruction notation

<<operand-notation>> lists the operand placeholders used in instruction
descriptions and encoding tables. Literal values, register names, mnemonics and
file names are shown in a monospaced font; hexadecimal values are prefixed with
`0x`, and an underscore may be used to separate digit groups (it is not part of the
value, for example `0xFFFF_FFF5`).

.Operand notation
[#operand-notation]
[%header,cols="1,2,4"]
|===
|Notation |Type |Description
|`RD` |Register reference |First register operand. In most instructions it is the
destination register, which is overwritten with the result.
|`RS` |Register reference |Second register operand, used as a source of data.
|`RO` |Register reference |Register offset used by the memory operands `[RD+RO]` and
`[RS+RO]`.
|`imm5` |Immediate |5-bit unsigned value. Encoded in one byte; see <<imm-operands>>.
|`imm8` |Immediate |8-bit value. Encoded in one byte.
|`imm32` |Immediate |32-bit value. Encoded in four bytes, little-endian.
|`+imm8` |Displacement |Signed 8-bit displacement, relative to the address of the
branch instruction.
|`[addr]` |Memory operand |The 32-bit word (or byte) stored at address `addr`.
|===

The register references `RD`, `RS` and `RO` may be either full 32-bit registers or
the lower byte of a register; see <<reg-ref>> for the encoding.

In the encoding tables, each column is one byte of the instruction. A cell names the
opcode macro or the operand encoded in that byte, and `--` marks a byte that the
instruction does not use. Bit ranges are written `m:n`, where `m` is the more
significant bit.

This chapter documents the complete instruction set of the CPU. Some instructions

for them, and one pair of instructions is not yet implemented by the CPU.

A number of instructions have two forms that differ only in the type of the second
operand: a register (`RD, RS`) or an immediate value (`RD, imm32`). The two forms
are separate opcodes, but they behave identically apart from the source of the
second operand.

=== Data movement instructions

The data movement instructions copy values between registers and memory. None of
them modifies the flags.

Alignment and access-width requirements are imposed by the memory region that is
accessed, not by the CPU; see <<memory-model>>. The `STR` and `LDR` instructions are
the only instructions that honour the access-size bit of a register reference
(<<reg-ref>>): with an 8-bit register reference, only one byte is transferred.

Moves a 32-bit value into a register. The source is either an immediate value or

----

Loads a value from memory into a register. The address is formed in the same way as
for `STR`.

.Syntax

LDR RD, [RS+RO]
----

----
RD = [imm32]

.Flags
None.

If `RD` is an 8-bit register reference, one byte is read into the lower 8 bits of
the register; bits 31:8 keep their previous value. Otherwise, four bytes are read
into the full 32-bit register, little-endian.

A bad memory access exception (<<exceptions>>) occurs if the address is not mapped,
if the region does not support the requested access width, or if a 32-bit load

Assembled; mnemonic `ldr`. The `[imm32]` and `[RS+imm32]` forms are not implemented
by the current assembler.

.Examples
----
ldr     r2, [r1]                ; r2 = word at the address in r1
ldr     rb6, [r4]               ; low byte of r6 = byte at the address in r4
----

=== Arithmetic and logic instructions

The arithmetic and logic instructions compute a result from the destination
register and a second operand, store the result in the destination register, and
update the flags. `CMP` and `TST` perform the same computation as `SUB` and `AND`
respectively, but discard the result; they are used to set the flags for a
following conditional branch.

The second operand is either a register (`RD, RS`) or an immediate value
(`RD, imm32`). Four instructions support a 5-bit immediate in their immediate form:
`SHL`, `SHR`, `ROL` and `ROR`. The two forms of each instruction are separate
opcodes and always access full 32-bit registers.

===== Difference between DIV and IDIV

`DIV` treats the operands as unsigned values and ignores their sign bits. `IDIV`
respects the signs of the operands and produces a signed quotient.

* Unsigned division of the operands `-11` (`0xFFFF_FFF5`) and `2` (`0x0000_0002`)
  produces `2_147_483_643` (`0x7FFF_FFFB`), because `0xFFFF_FFF5` is interpreted as
  `4_294_967_285`.
* Signed division of the same operands produces `-5`.

=== Flow control instructions

The flow control instructions change the program counter. Every branch condition has
three forms that differ in how the target address is computed: a relative
displacement, an absolute 32-bit address, and a register. `CALL` and `RET` manage
subroutine calls; `CALL` uses the stack, `RET` reads it back.

None of the flow control instructions modifies the flags.

[[condition-flags]]
==== Branch conditions

The conditional branch instructions test the `Z`, `S` and `V` flags. The `C` flag is
not used by any branch instruction, and the ISA defines no unsigned conditional
branch: comparisons performed by `CMP` and a conditional branch are always signed.

For a subtraction `RD - S = R`, the exclusive OR of the sign and overflow flags
(`S ^ V`) indicates whether the signed comparison of `RD` and `S` is correct:

* If `S ^ V = 0`, the result is correct and non-negative, so `RD` is greater than or
  equal to `S`. This covers two cases: `S = 0, V = 0` (the sign of the result is
  correct and reset) and `S = 1, V = 1` (the result would be negative but the
  subtraction overflowed, so the true result is positive).
* If `S ^ V = 1`, the result is negative, so `RD` is strictly less than `S`. This
  covers `S = 1, V = 0` (the sign of the result is correct and set) and
  `S = 0, V = 1` (the result would be positive but the subtraction overflowed, so the
  true result is negative).

Together with the zero flag, which is set when `RD = S`, this covers every possible
relationship between signed operands.

.Signed comparison conditions
[#comparison-conditions]
[%header,cols="1,2,2,3"]
|===
|Condition |Instruction |Test |Relationship after `CMP RD, RS`
|Equal |`JEQ`, `JZ` |`Z = 1` |`RD = RS`
|Not equal |`JNE`, `JNZ` |`Z = 0` |`RD != RS`
|Greater than |`JGT` |`Z = 0` and `S ^ V = 0` |`RD > RS`
|Greater or equal |`JGE` |`S ^ V = 0` |`RD >= RS`
|Less than |`JLT` |`S ^ V = 1` |`RD < RS`
|Less or equal |`JLE` |`Z = 1` or `S ^ V = 1` |`RD <= RS`
|===

`CALL` and `RET` have no condition; they use the stack to save and restore the
return address.

=== Stack instructions

The stack instructions move 32-bit values between a register (or an immediate value)
and the stack. `PUSH` decrements `SP` and writes a value; `POP` reads a value and
increments `SP`. The stack pointer therefore holds the address of the topmost
occupied word.

The access-size bit of a register reference is ignored by both instructions: the
full 32-bit register is transferred.

.Stack instruction encodings
[#stack-encodings]
[%header,cols="2,7*1",stripes=even]
|===
^|Instruction ^|Byte 0 ^|Byte 1 ^|Byte 2 ^|Byte 3 ^|Byte 4 ^|Byte 5 ^|Byte 6

|`PUSH imm32` |`PUSH_V32` 4+^|`imm32` 2+^|--
|`PUSH RD` |`PUSH_R` |`RD` 5+^|--
|`POP RD` |`POP_R` |`RD` 5+^|--
|===

[[stack-overflow]]
==== Stack overflow

The stack is limited only by the address space, and the CPU does not track its
bounds. Two conditions are nevertheless reported as a stack overflow exception
(<<exceptions>>):

* `SP` is less than 4 when a value is pushed. The push is not performed.
* `SP` is greater than `0xFFFF_FFFC` after a value is popped.

An overflowing stack is therefore only detected at the ends of the address space.
Software must ensure that `SP` points to a suitable region of memory before using
the stack.

.Syntax

.Operation

.Flags

.Exceptions
A stack overflow exception occurs if `SP` is less than 4.

.Support
CPU only: the current assembler has no `push` mnemonic.

Pops a 32-bit value from the stack into a register.

.Syntax

.Operation

==== NOP

Performs no operation. Execution continues with the next instruction.

.Syntax
----
NOP
----

.Flags
None.

.Support
CPU only: the current assembler has no `nop` mnemonic. A label on its own line
assembles to zero bytes and can be used as a placeholder.

==== HALT

Halts the CPU. Execution resumes when an interrupt request becomes pending; the CPU
then services the interrupt in the usual way.

.Syntax
----
HALT
----

.Flags
None.

.Support
Assembled; mnemonic `halt`.

.Examples
----
halt
jmpr    halt                    ; remain halted
----

==== INT

Raises an interrupt request on an IRQ line, as if a device had raised it. The
interrupt is serviced according to <<interrupts>>.

.Syntax
----
INT imm8
----

.Operation
----
irq_line[imm8] = pending
----

.Flags
None.

.Exceptions
A bad instruction exception (<<exceptions>>) occurs if `imm8` is greater than 31.

.Support
CPU only: the current assembler has no `int` mnemonic.

NOTE: `imm8` is an IRQ line number, not an IVT entry number. IRQ line 0 corresponds
to IVT entry 32, and line 31 to entry 63.

==== IRET

Returns from an interrupt or exception handler. The top 32-bit value of the stack is
loaded into `PC`. Unlike `RET`, `IRET` does not otherwise change the CPU state.

.Syntax
----
IRET
----

.Operation
----
PC = [SP]
SP = SP + 4
----

.Flags
None.

.Exceptions
A stack overflow exception (<<stack-overflow>>) occurs if `SP` is greater than
`0xFFFF_FFFC` after the pop.

.Support
Assembled; mnemonic `iret`.

.Examples
----
isr:
        ; ...
        iret                    ; return to the interrupted program
----

== Assembler support and directives

This appendix summarises what the Rust assembler in `tools/asm-rust` currently
accepts. It is provided because the assembler implements a subset of the ISA
described in <<instruction-set>>.

=== Supported mnemonics

.Mnemonics accepted by the current assembler
[%header,cols="1,2,3"]
|===
|Mnemonic |Operands |Notes
|`mov` |`RD, RS`; `RD, imm32`; `RD, label` |A label is encoded as its absolute
address. `RD` may be a byte register (`rbN`), but the access size is ignored.
|`str` |`[RD], RS`; `[RD+imm8], RS`; `[RD-imm8], RS`; `[RD+RO], RS` |`RD`/`RO` may be
byte registers. The `[imm32]` and `[RD+imm32]` forms are not implemented.
|`ldr` |`RD, [RS]`; `RD, [RS+imm8]`; `RD, [RS-imm8]`; `RD, [RS+RO]` |Same restrictions
as `str`.
|`add` |`RD, RS`; `RD, imm32` |
|`sub` |`RD, RS`; `RD, imm32` |
|`and` |`RD, RS`; `RD, imm32` |
|`not` |`RD` |
|`shr` |`RD, RS`; `RD, imm5` |The immediate must fit in five bits.
|`cmp` |`RD, RS` |
|`tst` |`RD, RS`; `RD, imm32` |
|`jmpr` |`label` |Relative branch; the label must be within `-128` to `+127` bytes.
|`jmpa` |`imm32`; `RD` |Absolute or register branch.
|`jeqr` |`label` |Relative branch if equal.
|`jner` |`label` |Relative branch if not equal.
|`call` |`imm32`; `RD` |A label can be used as the target of the immediate form.
|`ret` |-- |
|`halt` |-- |
|`iret` |-- |
|===

Instructions that are implemented by the CPU but have no assembler mnemonic:
`MUL`, `DIV`, `IDIV`, `OR`, `XOR`, `SHL`, `ROL`, `ROR`, `JGT`, `JGE`, `JLT`, `JLE`,
`PUSH`, `POP`, `NOP` and `INT`.

=== Registers

The assembler accepts register names without a leading `%` or `$`, and is not
case-sensitive about them:

* `r0` to `r7` select full 32-bit registers.
* `rb0` to `rb7` select the lower byte of a register (access size 1).
* `sp` selects the stack pointer. It is currently tokenised as a label rather than
  as a register, so it cannot be used as an operand.

=== Directives

.Directives
[%header,cols="1,2,3"]
|===
|Directive |Operands |Description
|`.set` |`NAME, value` |Defines a constant. `value` may be a number, a string, a
label, or another constant.
|`.origin` |`imm32` |Advances the location counter to the given address, filling the
gap with zero bytes.
|`.skip` |`imm32` |Declared but not implemented: using it aborts the assembler.
|`.strd` |`label` |Emits a 32-bit word containing the absolute address of `label`.
|`.strb` |`imm8` |Emits a single byte.
|`.strs` |`"text"` |Emits the characters of `text` followed by a terminating zero
byte.
|===

=== Assembly syntax

* Instructions, directives and labels are written one per line.
* A label is an identifier followed by a colon, for example `start:`.
* Comments begin with `;` and extend to the end of the line.
* Numbers may be written in decimal (`4096`) or hexadecimal (`0x1000`).
* Mnemonics must be written in lower case. Register names, constants and labels are
  case-insensitive.
