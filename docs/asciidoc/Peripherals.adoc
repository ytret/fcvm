== The FCVM bus controller

A device is not visible to the guest program directly. It is connected to the bus
controller, which gives it a memory-mapped region and an interrupt request line.
The guest program discovers the connected devices by reading the registers of the
bus controller.

This chapter describes how devices are connected and how the guest program
enumerates them. It does not describe the individual devices.

=== Overview

The bus controller provides:

* 32 device slots, numbered 0 to 31.
* A read-only register region in memory, used by the guest program to enumerate the
  connected devices.
* Automatic assignment of a memory-mapped region to every connected device.
* Automatic assignment of an interrupt request line to every connected device.

.Bus controller parameters
[#bus-params]
[%header,cols="2,2,5"]
|===
|Parameter |Value |Description
|Device slots |32 (0 to 31) |Maximum number of devices that can be connected at the
same time. Defined as `BUS_MAX_DEVS` in `inc/fcvm/busctl.h`.
|Register region |`0xF000_0000` to `0xF000_0184` |Address range of the bus controller
registers. The end address is exclusive. The start address is `BUS_MMIO_START`.
|Register region size |388 bytes |4 bytes of status plus 12 bytes per device slot.
|Device region range |`0x0000_0000` to `0xF000_0000` |Address range from which the
memory-mapped regions of the devices are taken. The end address is exclusive. The
start address is `BUS_DEV_MAP_START`.
|Interrupt request lines |0 to 31 |Assigned to devices in connection order. Line
_n_ corresponds to IVT entry 32 + _n_.
|===

=== Device connection

Devices are connected by the host that runs the virtual machine, not by the guest
program. When a device is connected, the bus controller:

. Selects the lowest-numbered free slot.
. Assigns the device the first free memory-mapped region at or above
  `0x0000_0000`, sized as requested by the device.
. Assigns the device the lowest unused interrupt request line.

A failed connection consumes no resources: if any of the steps above fails, the
device is not connected, and the next connection attempt is given the same slot,
region and interrupt line.

.Device connection errors
[#connect-errors]
[%header,cols="2,3,5"]
|===
|Condition |Error |Description
|No free slot |`VM_ERR_BUS_NO_FREE_SLOT` |All 32 slots are used.
|Region does not fit |`VM_ERR_BUS_NO_FREE_MEM` |The requested region does not fit
below `0xF000_0000`. Regions are packed from `0x0000_0000` upwards, so this means
that the regions of the already connected devices leave no room.
|Region not available |`VM_ERR_MEM_USED` |The requested region overlaps an already
mapped region, including the bus controller registers.
|Region limit reached |`VM_ERR_MEM_MAX_REGIONS` |The memory controller has no free
region descriptor left. The bus controller registers occupy one of the 33, leaving
32 for the devices.
|===

WARNING: The IVT occupies the first 1 KiB of the address space (addresses
`0x0000_0000` to `0x0000_03FF`), and the bus controller assigns device regions from
`0x0000_0000` upwards. The first device connected to the bus must therefore provide
the memory for the IVT: its region has to cover the whole IVT, and its memory
interface has to serve the IVT reads. Otherwise the CPU cannot read the vector of
an exception or interrupt, and raising one causes a bad memory exception; if that
vector cannot be read either, the CPU ends up in a triple fault.

=== Bus controller registers

The bus controller registers are read-only. They report the state of the bus and
the resources that were assigned to each device; writing to them is not possible
and there is no way to connect or disconnect a device from the guest program.

==== Register map

.Register map
[#reg-map]
[%header,cols="2,3,1,5"]
|===
|Offset |Register |Size (bytes) |Description
|`0x00` |<<reg-slot-status,Slot status register>> |4 |Occupancy of the 32 device
slots.
|`0x04 + 0x0C*x` |<<reg-dev-desc,Slot device descriptor>> |12 |Resources assigned
to the device in slot _x_, where _x_ is 0 to 31.
|===

All offsets in this chapter are relative to the start of the register region,
`0xF000_0000`. The slot device descriptor of slot _x_ occupies the region offsets
`0x04 + 0x0C*x` to `0x0F + 0x0C*x`, so the last descriptor, of slot 31, ends at
offset `0x183`.

==== Register access rules

The registers are accessed with 32-bit reads, using the `LDR` instruction of the
instruction set manual. The region does not support byte accesses, and it is not
writable.

.Register access rules
[#reg-access]
[%header,cols="3,5"]
|===
|Access |Result
|32-bit read of a register |The value of the register.
|32-bit read at any other offset |Bad memory exception.
|8-bit read |Bad memory exception. The region does not implement byte accesses.
|Any write |Bad memory exception. The region is read-only.
|===

A bad memory exception is IVT entry 1; see the instruction set manual for the
exception and interrupt model.

==== Slot device descriptor

The slot device descriptor describes the resources that were assigned to the
device in a slot. Every slot has a descriptor, whether or not a device is connected
to it; the descriptor of a free slot reads as all zeros. The descriptor is three
32-bit words long, at the region offsets `0x04 + 0x0C*x`, `0x08 + 0x0C*x` and
`0x0C + 0x0C*x`, where _x_ is the slot number.

.Slot device descriptor word map
[#reg-dev-desc]
[%header,cols="2,3,1,5"]
|===
|Offset |Word |Size (bytes) |Description
|`0x04 + 0x0C*x` |<<reg-dev-desc-start,Mapped region start>> |4 |First byte of the
memory-mapped region of the device.
|`0x08 + 0x0C*x` |<<reg-dev-desc-end,Mapped region end>> |4 |End of the
memory-mapped region of the device, exclusive.
|`0x0C + 0x0C*x` |<<reg-dev-desc-class-irq,Device class and IRQ line>> |4 |Class of

=== Enumerating connected devices

A guest program enumerates the connected devices by reading the slot status
register, and then reading the descriptor of every slot whose status bit is set.

.Device enumeration
----
status = load32(0xF0000000)          ; slot status register

for x in 0 to 31
    if status & (1 << x)             ; device is connected to slot x
        base  = 0xF0000004 + 12 * x  ; slot device descriptor
        start = load32(base + 0)     ; first byte of the device region
        end   = load32(base + 4)     ; end of the device region, exclusive
        word  = load32(base + 8)
        class = (word >> 8) & 0xFF
        irq   = word & 0xFF
----

Each device occupies exactly one slot and is assigned exactly one memory-mapped
region and one interrupt request line. A device cannot be disconnected, so its
assignment does not change while the virtual machine runs, and a snapshot and a
restore preserve the slots, the regions and the interrupt lines of the connected
devices.
